# Buddy Proxy v0.7.5

## v0.7.5 · 2026-11-15 · 签到审计、工具 Schema 与额度冷却自愈

特别感谢 [@240xu](https://github.com/240xu) 在 [#67](https://github.com/wnddd839/buddy-proxy/pull/67)、[#69](https://github.com/wnddd839/buddy-proxy/pull/69)、[#70](https://github.com/wnddd839/buddy-proxy/pull/70)、[#71](https://github.com/wnddd839/buddy-proxy/pull/71) 提供实测、根因分析与实现。四个 PR 均逐项审核并补修后纳入；以下说明以最终实现为准。

### 改进与修复

- **签到与推理**：同时转发客户端推理对象与生效的 `reasoning_effort`，仅传对象时提升其 effort；显式扁平字段优先，监测统计遵循相同口径。窗口随机改为均匀分布，全天模式使用小时权重；整批错开明确为每天相同的固定时刻。
- **不丢签到、不改变启动契约**：延迟窗口内的到点账号串行处理完再推进游标，避免单轮 `break` 永久丢失其余账号；仍然启动不补签。日志 `at` 记录计划时刻，新增 `ranAt` 记录执行时刻；保留期、重试间隔、排序和页面展示按执行时刻，旧记录回退 `at`。
- **工具 Schema**：修复裸属性字典及属性内布尔 `required`，消除这类定义触发的上游 11129；合法对象、数组、引用、组合及其他约束保持不变，不就地修改请求。并非所有 11129 都能据此解决。
- **额度冷却自愈**：区分 `quota` 与 `upstream` 来源，仅当余额恢复或 unlimited 有证据时解除额度冷却；旧数据依据重置时间指纹兼容。新会话补探允许纳入最多 4 个额度冷却账号，避免永久无法重探。
- **源区用尽才跳**：路由新增 `mode=onExhausted`，旧规则缺省仍是 `always`。有同区候选先换同区账号；用尽后才推进原始链，实际 429 也能消费备用跳。同站跳转保留失败账号排除列表，显式站点与固定账号不套用路由。
- **管理台可观测性**：手动刷新同时拉取两站启用账号余额，保留真实账号级与模型级限流；模型标签显示当前快照的可用、冷却、额度不足账号数，计入积分下限，不保证上游实时可用或支持该模型。
- **可选敏感转储**：新增 `CODEBUDDY_PROXY_DUMP_FAILURES`，默认关闭，配置后重启生效。失败请求可写入完整对话及诊断，最多保留最近 6 组、每份请求约 64 MiB；使用唯一文件名，并只清理自身前缀文件。此数据未经内容脱敏，不应上传公开 Issue。

### 审核与验证

`gofmt`、`go vet ./...`、`go test ./...`、`go test -race ./...` 与构建通过；PR CI 包含 Linux 构建与 Docker 启动/鉴权/持久化冒烟。真实二进制浏览器端到端回归覆盖配置保存、两种路由时机持久化、模型可用数、草稿/失败恢复、XSS 转义及桌面/窄屏。复现依赖隔离的上游模拟，不将贡献者生产实测冒称为本次在线实测。

### 升级

替换对应平台二进制或更新 Docker 镜像；不覆盖 `.env`、账号池、签到密钥及历史文件。现有路由默认不变；随机签到分布会变化，但固定时刻不变。新旧签到日志兼容，无需手动迁移。千问上游建议 [#21](https://github.com/wnddd839/buddy-proxy/issues/21) 仍为未实现需求，本版不包含 QwenWork 支持。
